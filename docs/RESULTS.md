# Recorded software results - Mounam 2.0

These results were generated by the shared C++ inference engine on human command
recordings mixed with generated noise and simulated microphone paths. They are
not measurements from the physical prototype or actual defence environments.

Corpus: 600 two-second pairs, 120 speaker identities; 360 training,
120 validation and 120 test examples. Speaker groups are disjoint: 58/24/38.
The test means below use 90 speech examples; 30 noise-only examples are separate.

| Mode | Output SNR (dB) | SI-SDR (dB) | STOI | PESQ-WB |
| --- | ---: | ---: | ---: | ---: |
| Original output | 4.99 | 4.82 | 0.768 | 1.64 |
| Classical DSP | 10.46 | 9.46 | 0.795 | 2.05 |
| Neural hybrid | 13.85 | 13.45 | 0.842 | 2.31 |

Original output includes the common DC-removal stage. The raw input mean SNR is
5.56 dB. Comparisons retain the same digital output gain and clean target.

## Model and protocol evidence

- Speech model ID: `5c9e4fb2a9b2fada`.
- Neural model ID: `b01f7e44d2512bad`.
- Neural validation gain MSE, float / int8: 0.017393 / 0.017258.
- Maximum validation gain change due to weight quantization: 0.041545.
- Eight-band model: 816 int8 weights, 32 float32 scales and 32 float32 biases (1,072 bytes).
- Training features/targets and evaluation use the actual portable firmware C++ core.
- Checkpoints are selected by validation loss; test speakers are evaluated afterwards.
- Per-example reports and valid metric counts are retained under `models/public_*.json`.
- Validation reports are retained separately; some short validation utterances cannot be scored by PESQ and retain explicit failure reasons.

## Targets and remaining limits

The global test means do **not** yet meet all stated SNR >15 dB, STOI >0.85 and
PESQ >2.5 targets. Individual scenarios differ; the table above must not be used
to claim every condition passes. The benchmark is short English commands and
generated noises, not continuous tactical speech or a field trial.

No physical board was connected for these software runs. MCU processing time,
whole acoustic latency, power, microphone clipping, headphone output and real
defence-noise robustness need the separate hardware validation protocol.
